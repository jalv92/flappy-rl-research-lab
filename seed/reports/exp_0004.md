# Experiment 4: H004 — Rolling back to the best snapshot and halving the learning rate when training collapses

- Stage: **screening** (exploratory) · profile `full_research` · code `2ae67e4` · variant source `e280d2ad9cbf`
- Decision: **inconclusive**
- Conclusion: no significant difference. auc: diff -0.104 (95% CI -0.229..+0.0209, P(improve)=0.26); final_mean: diff -49 (95% CI -142..+53.1, P(improve)=0.40)

## Hypothesis
- Area: adaptive_schedules
- Motivation: Collapses are detectable online: the smoothed training-episode length drops sharply. A reliable progress indicator can gate the optimiser instead of a fixed schedule.
- Modification: Snapshot networks at each new best smoothed episode length; when it falls below half of that best, restore the snapshot and halve the learning rate (5000-step cooldown).
- Expected benefit: Higher final-policy mean and fewer degradations at the same step budget.
- Failure modes considered: The indicator is noisy under epsilon-greedy; spurious rollbacks waste steps; the lower learning rate can freeze a mediocre policy.
- Prior work: Related: checkpoint rollback, reduce-LR-on-plateau, trust-region ideas. No specific prior paper identified for this exact rule.
- Novelty status: unverified
- Baseline: xdqn control: identical hyperparameters, step budget, seeds and evaluation schedule
- Criteria: Primary: validation AUC (sample efficiency) and final-policy validation mean, per training seed, candidate vs control. Promising only if a 95% bootstrap CI of the difference excludes 0 in the favourable direction and no primary metric is significantly worse. Secondary: degradation count, seed CV, wall-clock ratio.
